# 平台故事角色库

故事模板和角色由后端平台素材库统一管理。前端通过 `/storyCharacter/v1/template/list` 读取模板，通过 `/storyCharacter/v1/list` 按模板读取角色；平台管理员在“平台素材库”内的故事模板管理页创建、编辑模板，在同一素材库页面上传角色。普通用户可以查看和选择，写接口由后端平台管理员权限最终控制。

`public/story-characters/` 中的旧图片仅作为历史本地素材保留，不再作为生产环境角色列表或任务图片地址的来源。前端不依赖 `STORY_CHARACTER_PUBLIC_BASE_URL`。

## 图片要求

平台管理员上传 PNG、JPEG 或 WebP，大小不超过 10 MB。数据库只保存对象存储路径 `file_path`，不保存 `image_url`；后端每次返回角色列表或生成任务时，根据当前配置重新生成图片地址。故事生成服务端会再次按模板和角色 ID 从后端读取并校验角色，避免客户端篡改名称、描述或图片地址。

## 首帧与缓存

真实背景直接与角色图多图编辑；AI 背景先生成无角色底图，再与角色图多图编辑。首帧准备结束后，主会话对照角色图验收，再渲染视频。

每份方案在 `.tasks/xhs-video-task-{id}/runs/{fingerprint}/` 保存中间产物。指纹包含角色配置、首帧计划与动态计划。同方案可续跑，不同角色或分镜使用不同缓存。成片与清单写回原来的统一路径，草稿箱无需变更。

## 检查

执行 `node scripts/test-story-characters.cjs` 检查服务端角色数据格式、HTTPS 图片地址和紧凑故事任务。测试使用模拟 AI 返回，不调用付费服务。
